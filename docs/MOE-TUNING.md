# MoE в SAS: переносимость и ручная настройка

Разбор размещения экспертов актуален для SAS 0.8.5 и встроенному llama.cpp b10809. Большие модели для этого анализа не скачивались.

## Ответ на главный вопрос

**Алгоритм подходит другим совместимым GGUF MoE, но одинаковые числа настроек переносить нельзя.** SAS читает архитектуру, количество экспертов, размеры экспертных тензоров, слои и параметры attention из заголовка файла. Название «4x7B» не служит основанием для выбора. Расчёт повторяется по контексту, KV-кэшу, резерву и свободной VRAM устройства.

Для Dense алгоритм экспертов не применяется: пользовательские потоки, пачки и прочие параметры сохраняются. К внешнему API флаги запуска локального llama.cpp не относятся.

| Случай | Поведение SAS |
| --- | --- |
| Один GGUF MoE, стандартные скалярные метаданные attention, распознанные экспертные тензоры | Подбор числа первых слоёв с экспертами на CPU |
| Другая подходящая архитектура, квантование, число экспертов или GPU | Новый расчёт по метаданным и памяти |
| Dense | Без MoE-подбора |
| Несколько частей GGUF | Без собственного подбора: первая часть не даёт размер всей модели |
| MLA, рекуррентное состояние, разные параметры attention по слоям | Ручное размещение и доступный подбор llama.cpp; стандартная формула не выдаётся за точную |
| Неполные метаданные или нераспознанные экспертные тензоры | Явная причина отказа от собственного автоподбора |
| Архитектура не поддерживается встроенным llama.cpp | Настройки SAS не добавляют поддержку, запуск сообщит ошибку |

Это анализ реализации. Автотесты разных архитектурных имён и метаданных используют небольшие синтетические GGUF. Это не означает запуск всех семейств реальными весами. Реальные проверки выполняются на уже имеющихся SAINEMO Dense/MoE и BGE.

## Не путайте три параметра

**Всего экспертов** — свойство обученных весов. Четыре эксперта нельзя превратить в восемь настройкой: нужны другие веса.

**Активных экспертов · переопределение** — настройка маршрутизации. `0` берёт значение GGUF; ручное число ограничено количеством экспертов. Автоподбор его не меняет. Переопределение может ухудшить связность, не удаляет остальные веса и не гарантирует уменьшение VRAM. Для начала оставляйте `0`. Используется официальный [механизм --override-kv](https://github.com/ggml-org/llama.cpp/blob/b10809/tools/server/README.md#usage).

**Слоёв с экспертами в RAM** — размещение экспертной части первых N слоёв на CPU, а не число активных экспертов. Значение `--n-cpu-moe` подтверждено в [документации llama.cpp b10809](https://github.com/ggml-org/llama.cpp/blob/b10809/tools/server/README.md#usage).

В вашей `M-MOE-4X7B-Dark-MultiVerse-UC-E32-24B-D_AU-Q5_k_s.gguf` прочитаны четыре эксперта и четыре активных эксперта. Нельзя автоматически считать, что работают только два из четырёх. Ранее эта модель искажала факты даже при правильном контексте. Размещение весов не исправляет качество обучения.

## Расчёт и ограничения

Для стандартного attention приблизительно:

```text
KV = слои × контекст × KV-головы ×
     (размер ключа × байты типа K + размер значения × байты типа V)
Бюджет весов GPU = свободная VRAM − резерв − KV
```

SAS складывает размеры экспертных тензоров первых слоёв, пока оставшиеся веса укладываются в бюджет. Если размеры известны по слоям, не предполагается их равенство. «Помещается» означает оценку, а не гарантию выделения памяти.

Квантизированный KV содержит служебные масштабы. Для Q5 расчёт исправлен по размеру целого блока, а не только битам значения. Форматы описаны в [структурах GGML b10809](https://github.com/ggml-org/llama.cpp/blob/b10809/ggml/src/ggml-common.h). Дополнительные рабочие буферы, графы и особенности драйвера учитываются лишь резервом; результат приблизительный.

У [DeepSeek MLA](https://github.com/ggml-org/llama.cpp/blob/master/src/models/deepseek2.cpp) отдельные ранги и размеры attention. При таких метаданных SAS воздерживается от собственного автоматического переопределения. Это не запрет запуска.

Встроенный `--fit` подбирает незаданные параметры под память; он не обязан исправлять явно заданные значения или несовместимые комбинации. При необходимости уменьшайте контекст, физическую пачку и GPU-слои. См. [официальные параметры fit](https://github.com/ggml-org/llama.cpp/blob/b10809/tools/server/README.md#usage).

## Ручное управление

Откройте «Настройки → Модели и API → Локальные модели → Параметры запуска · память, CPU и MoE».

- Расширенные поля редактируются и при загруженной модели: значения сохраняются для следующего запуска. Работающий процесс не меняется.
- Во время генерации сохранение настроек блокируется.
- Правка «Слоёв с экспертами в RAM» включает ручное размещение. Можно предварительно выключить «Автонастройка MoE».
- Активные эксперты задаются независимо; `0` возвращает GGUF-маршрутизацию.
- Максимумы экспертов и слоёв ограничены метаданными; сервер проверяет их повторно.
- Устройство, контекст, GPU-слои и embedding-конфигурация меняются после остановки моделей.
- Для применения нажмите «Остановить модель», затем «Запустить модель». Сведения о текущем процессе показываются отдельно.

Дождитесь сведений GGUF. Экспертные поля для распознанной Dense-модели неприменимы; это отличается от временной блокировки генерацией.

## Порядок проверки другой модели

1. Начните со штатных экспертов, RoPE из GGUF и умеренного контекста.
2. Проверьте архитектуру и устройство. NVIDIA использует CUDA, доступные AMD/Intel — Vulkan; скорость конкретного GPU отдельно не обещается.
3. Посмотрите применимость оценки SAS и резерв памяти.
4. Выполните «Замерить скорость». Сравните также качество одинаковых заданий прозы, сводки и ответа ведущего.
5. Меняйте один параметр за раз. Меньшая физическая пачка может снизить пики памяти при обработке промпта, но не гарантирует ускорения.
6. Проверьте длинную историю: короткий замер не измеряет её стоимость.
7. При ручных экспертах сравните имена, факты, завершение предложений и служебные ответы. Изменение их числа не является универсальным улучшением.

Токены/с нельзя достоверно вывести только из «24B» или «8x7B»: влияют CPU, RAM/VRAM, PCIe, квантование, архитектура, промпт и backend. SAS показывает реальное измерение модели на устройстве.

## Режимы и память

Флаги относятся к загруженному локальному процессу и не создают общей памяти сюжетов. Одиночная история, D&D/НРИ и фанфик выбирают свои документы и инструкции, даже если используют одну модель.

Локальные сэмплеры — базовый набор; специальные режимы задают поверх него собственные параметры ответа. Для векторизации нужна отдельная encoder-модель или embeddings API. Число экспертов чат-модели не включает embeddings.

Практический процесс: [гайд Фанфика](FANFIC-GUIDE.md).


## РП со старыми шаблонами в 0.8.5

Авторазмещение экспертов и адаптация промпта решают разные задачи. Первое распределяет память и вычисления по CPU/GPU; второе помогает старым Alpaca-шаблонам отделить персонажа от поста игрока. Архитектура MoE сама по себе не включает этот адаптер. Dense с другим шаблоном, внешние API, Фанфик и ведущий D&D не получают профиль обычного РП.

Профиль РП: Repeat penalty 1.03, окно 128; DRY 0.5, окно 256, разрешённая длина 4. Он применяется к базовым значениям сэмплеров; другие ручные значения сохраняют приоритет. Выключение «Адаптация Alpaca для РП» оставляет только ваши настройки. Исходный пост и история не сокращаются в хранилище. Подавление повторов не проверяет смысл ответа; корректно найденный источник ещё не гарантирует, что модель перескажет его верно.

«Параметры запуска → Шаблон диалога»: по умолчанию GGUF. Ручные Llama 3, Mistral v1/v3, ChatML и Command R доступны для моделей, которым они подходят, после перезапуска. [Автор M-MOE-4X7B](https://huggingface.co/DavidAU/Mistral-MOE-4X7B-Dark-MultiVerse-Uncensored-Enhanced32-24B-gguf) описывает несколько вариантов шаблонов и англоязычную модель. На имеющейся Q5_K_S проба Llama 3 не улучшила РП и дала посторонний текст; SAS не меняет шаблон этой модели автоматически.
