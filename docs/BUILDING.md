# Запуск и сборка SAS

## Требования

- Node.js **22 или новее** и npm. Проверка: `node --version`, `npm --version`.
- Git для клонирования. Для установки зависимостей в первый раз нужна сеть.
- Windows 10/11 x64 для готовой настольной поставки и её упаковки. Исходный веб-сервер работает на поддерживаемой Node.js системе; встроенные Windows-движки на другие ОС не переносятся.
- Для сборки полного Windows-пакета нужны подготовленные движки. Для интерфейса, API-подключения и разработки они не обязательны.

Все команды ниже выполняются в корне репозитория. Папка может содержать пробелы. Запуск от администратора обычно не требуется.

## Чистая установка

```sh
git clone https://github.com/Padparaja-Ge/Super-AI-Story.git
cd Super-AI-Story
npm ci
npm test
npm run build
```

`npm ci` устанавливает версии из lock-файла, включая Electron. Он не скачивает GGUF-модели чата, модели ComfyUI или дополнительные голоса. Зависимости занимают заметный объём диска; установка может занять несколько минут.

## Electron из исходников

```sh
npm run build
npm run desktop
```

Скрипт запуска использует Electron из зависимостей. В Windows создаёт отдельную оболочку с именем и значком SAS, сохраняя исходный npm-пакет Electron.

После изменения React-кода повторите сборку. Для работы с горячим обновлением используйте веб-режим разработки.

Серверные TypeScript-модули памяти находятся в `server/rag/ts/`. `npm run build` также компилирует их в совместимые с Node `.mjs`. Для отдельной проверки используйте `npm run build:server`; для проверки актуальности готовых файлов — `node scripts/build-rag.mjs --check`. API и пример интеграции описаны в [DND-MEMORY-API.md](DND-MEMORY-API.md).

## Веб-приложение

```sh
npm run build
npm run web
```

Откройте **http://127.0.0.1:3212**. По умолчанию доступ разрешён только с этого компьютера. Консоль остаётся запущенной; **Ctrl+C** останавливает сервер. Для веб-оболочки уже работающего ядра: `npm run web:shell` с той же папкой данных.

`npm start` запускает непосредственно backend API; для обычного веб-пользования используйте `npm run web`, который применяет веб-конфигурацию и обслуживает интерфейс.

Для разработки:

```sh
npm run dev
```

Интерфейс — `127.0.0.1:5173`, API — `127.0.0.1:3210`. Остановка общей команды завершает оба процесса.

## Сборка приложения без локальных движков

В Windows:

```sh
npm run package:app
```

Результат: `release/<версия>/windows/app/SAS.exe` и соседние файлы Electron. Это готовое приложение без встроенных LLM/TTS-движков; API-подключения доступны. Переносите всю папку `app`, а не один EXE. Генерация локальными моделями потребует отдельно подготовленных компонентов.

## Подготовка полного Windows-пакета

### Из готового официального ZIP

Скачайте полный пакет SAS из Releases и проверьте его SHA-256 по `SHA256SUMS.txt`. Затем:

```sh
npm run prepare:runtime -- --archive "D:\Downloads\SAS-Windows-0.9.9.zip"
npm run package:win
```

Подготовка извлекает только движки из `engines/` в локальную `runtime/`, проверяет размеры и хеши файлов по индексу пакета. Она не копирует пользовательские данные и не устанавливает модели чата.

### Отдельная подготовка компонентов

Если готового ZIP нет, компоненты можно подготовить из закреплённых источников:

```sh
npm run prepare:models
npm run prepare:silero
npm run package:win
```

Эти две команды подготовки явно скачивают необходимые компоненты: llama.cpp CPU/CUDA/Vulkan, Silero RU/EN и его Python-среду. Проверьте доступное место и условия моделей перед запуском. Команда `package:win` сама ничего из этого не скачивает и при отсутствии файлов указывает, что подготовить.

Для дополнительного профиля Kokoro доступна `npm run prepare:speech`; она загружает его веса и не нужна для стандартной поставки с Silero. Исходники поддерживают все перечисленные движки, но стандартный готовый пакет включает только Silero.

## Результаты упаковки

`npm run package:win` выполняет сборку и упаковку текущей версии из `package.json`:

```text
release/<версия>/
  windows/                   Готовая распакованная поставка
    SAS.exe                  Небольшой запускатель
    app/                     Electron и код приложения
    engines/                 llama.cpp и среда озвучки
    Start-SAS-Web.cmd         Самостоятельный веб-сервер
    Stop-SAS-Web.cmd          Остановка сервера
    Repair-SAS.cmd            Проверка и восстановление
  installer/                 Небольшой установочный комплект
  SAS-Windows-<версия>.zip    Полная поставка
  SAS-Start-<версия>.zip      Установочный комплект
  SAS-Web-Launcher.zip        Команды запуска для совместимой готовой поставки
  SHA256SUMS.txt
  publication-input.json     Локальный индекс результатов упаковки
```

`staging/`, `build/` и `builder.json` — промежуточные результаты внутри папки этой версии; они не публикуются в Git. Программа и её двигатели не распаковываются заново при каждом запуске.

Упаковка выполняется из исходников в изолированной папке. В готовый пакет не входят `src`, тесты, личные данные, `.env`, журналы, каталог Git и GGUF-модели чата. Лицензии и уведомления включаются в пакет.

## Веб-архив для Node.js

```sh
npm run package:web
```

Архив `release/<версия>/SAS-Web-<версия>.zip` содержит собранный интерфейс, сервер и необходимые исходные ресурсы. Для его запуска нужны Node.js 22+ и `npm ci --omit=dev`, затем `npm run web`. Веб-архив не содержит Windows-движков и весов моделей.

## Настройки и переменные окружения

| Параметр | Назначение |
| --- | --- |
| `SAS_DATA_DIR` | Отдельный каталог данных; абсолютный путь удобен для нескольких независимых установок |
| `SAS_WEB_CONFIG` | Путь к `web-server.json` |
| `SAS_WEB_HOST`, `SAS_WEB_PORT` | Параметры прослушивания исходного веб-сервера |
| `SAS_BACKEND_URL` | Адрес совместимого уже запущенного backend для оболочки |
| `SAS_LLAMA_DIR` | Папка подготовленных llama.cpp-движков |
| `SAS_SPEECH_BUNDLE_DIR` | Папка включённых в поставку компонентов озвучки |
| `SAS_DISABLE_EXTENSIONS=1` | Безопасный запуск без пользовательских исполняемых расширений |

Секреты внешних сервисов задаются на backend; пример — `.env.example`. Не добавляйте их в `VITE_*`, клиентские файлы, примеры или Git.

Для ручной настройки сети скопируйте `web-server.example.json` в `web-server.json`. Если рабочего файла нет, сервер использует безопасные настройки для localhost; интерфейс создаёт файл при сохранении сетевых настроек. Рабочий файл может содержать ключ и исключён из Git вместе с `.env` и `data/`. Упаковщики берут только проверенный шаблон без ключа, а не настройки компьютера сборщика.

## Проверка перед публикацией

1. `npm test` и `npm run build`.
2. Запуск исходного веб-интерфейса и Electron с отдельным `SAS_DATA_DIR`.
3. Установка полного ZIP и стартового комплекта в чистые папки без Node.js в PATH.
4. Проверка веб-старта, повторного запуска, остановки и сообщения об ошибке занятого порта.
5. Проверка локальных движков и выбранных интеграций при наличии соответствующих моделей.
6. Контрольные суммы, лицензии, отсутствие личных данных и соответствие версии тега.

Наличие автоматических тестов не заменяет проверку на другом оборудовании. Не обещайте одинаковую скорость для разных моделей, устройств и длины контекста.

## Диагностика

- **Нет Node.js:** установите поддерживаемую версию с https://nodejs.org/en/download и откройте новый терминал.
- **Нет `dist/index.html`:** выполните `npm run build`.
- **Порт занят:** остановите предыдущий веб-сервер или измените порт; не завершайте случайные процессы.
- **Ядро другой версии:** закройте прежние окна и веб-серверы, подождите завершения ядра и повторите запуск.
- **Не подключается другое устройство:** проверьте адрес, режим IP-списка, ключ, брандмауэр и маршрутизацию. `127.0.0.1` относится только к устройству, на котором открыт браузер.
- **Ошибка расширения:** используйте безопасный режим и отключите неисправный пакет.
- **Ошибка модели:** проверьте путь, устройство, фактическое окно контекста, шаблон диалога и совместимость embeddings API.

Исходные команды запуска и одноимённые команды готовой поставки имеют разные задачи: первые устанавливают npm-зависимости и собирают интерфейс, вторые запускают или устанавливают уже собранную программу.
