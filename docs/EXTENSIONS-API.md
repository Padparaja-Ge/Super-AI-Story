# SAS Extensions · Tutor / API / FAQ

SAS API 2: расширения интерфейса и доверенные Node.js-модули. Все примеры работают без SillyTavern. Устанавливайте только проверенный код: frontend имеет доступ к странице и API SAS, backend — права процесса Node.js. Это не песочница. Установка сама по себе ничего не запускает.

## 1. Быстрый старт

Откройте «Расширения», скачайте «Рабочий пример», установите JSON обратно через «Установить ZIP / JSON». Включите его после просмотра исходников. В меню появится «Заметки кампании», в верхней панели — команда открытия заметок. Это отдельное хранилище расширения: заметки не попадают в память или LLM автоматически.

Минимальный manifest.json:

```json
{
  "apiVersion": 2,
  "id": "my-extension",
  "name": "Моё расширение",
  "version": "1.0.0",
  "description": "Своя страница и инструменты",
  "frontend": "index.js",
  "permissions": ["studio:full-access"],
  "styles": ["style.css"],
  "modes": []
}
```

Файлы index.js и style.css находятся рядом с manifest.json. Архив ZIP должен содержать manifest.json в корне, без внешней папки. Поддерживается также JSON-пакет {"manifest": {...}, "files": {"index.js": "исходный JS", "style.css": "CSS"}}. Старый SAS JSON-плагин с prompt/regexRules импортируется прежней кнопкой и не является исполняемым API 2.

## 2. Страница, кнопка и React

```javascript
export function activate(sas) {
  sas.registerPage({
    id: 'tools', title: 'Мои инструменты',
    mount(container, context) {
      const button = document.createElement('button');
      button.textContent = 'Показать текущую историю';
      button.onclick = () => sas.notify(sas.getContext().chatId || 'История не выбрана');
      container.append(button);
      return () => button.remove();
    }
  });
  sas.registerCommand({
    id: 'open-tools', title: 'Мои инструменты', slot: 'topbar',
    run: () => sas.navigate('extension:my-extension/tools')
  });
}
```

activate(sas) вызывается при включении. Можно вернуть функцию очистки, в том числе из async activate. Для отложенной очистки используйте sas.onDispose(fn). Страницы и команды снимаются автоматически при выключении или обновлении. Каждый id уникален внутри расширения. Навигация на встроенные разделы: chat, fanfic, wizard, storybooks, characters, personas, lore, memory, models, plugins, multiplayer, technical, settings, appearance.

Для React используйте sas.ui.React и sas.ui.createRoot. Это та же версия React, что использует оболочка. В mount создайте root, в cleanup вызовите root.unmount(). Можно поставлять собранный JS без npm на компьютере пользователя. Относительные ES-import работают; при обновлении меняется URL версии всего пакета.

## 3. Панели и изменение оформления

```javascript
export function activate(sas) {
  sas.registerSlot({
    id: 'message-copy', slot: 'message-actions',
    mount(element, context) {
      const button = document.createElement('button');
      button.textContent = 'В заметки';
      button.onclick = () => sas.storage.update(data => {
        data.lastMessage = context.content;
      });
      element.append(button);
      return () => button.remove();
    }
  });
}
```

Слоты: sidebar, topbar, workspace-top, workspace-bottom, settings, message-actions. В message-actions дополнительно передаются chatId, messageId, role и content. mount возвращает cleanup. При изменении контекста контейнер получает DOM-событие sas:context с detail; подписка на него также должна удаляться в cleanup. getContext() всегда возвращает актуальные view, chatId, task.

CSS-файлы manifest подключаются при включении и удаляются при выключении. Можно менять всю оболочку через CSS и DOM. Собственные классы начинайте с id расширения, чтобы случайно не затронуть соседние панели. Внутренние CSS-классы SAS не являются стабильным API и могут изменяться между версиями. Прямые DOM-изменения отменяйте через cleanup. Не меняйте содержимое message-body для сохранения текста: это только отображение, React может его перерисовать.

## 4. Состояние, события и запросы

```javascript
const state = await sas.state.read();
await sas.state.update(draft => {
  const chat = draft.chats.find(c => c.id === sas.getContext().chatId);
  if (chat) chat.title = 'Новое название';
});
const off = sas.on('stateChanged', ({revision}) => console.log(revision));
// off() снимает подписку; при выключении она снимается автоматически.
```

state.read() получает сохранённое состояние. state.update(fn) использует очередь оболочки, проверку ревизии и сохранение SAS. fn должен быть синхронным. Изменения во время генерации отклоняются. Не сохраняйте собственные данные в произвольные поля state: используйте storage. Защищённые сервером списки (комнаты, работающие генерации, AI-мастер и фанфик) меняются их профильными API.

События: stateChanged ({revision}), viewChanged ({view, chatId, task}), taskChanged (текущая задача или null). События не включают всю историю автоматически. Обработчик может явно запросить данные через state.read(). Исключения одного обработчика не прерывают остальные.

request(path, body?, method?) — тот же JSON API, что использует SAS, с префиксом /api и заголовком X-SAS-Client. Примеры: request('/state'), request('/prompt', {chatId, content:''}), request('/multiplayer/status'), request('/generations', {chatId, content:'...'}). Для изменения защищённых сущностей сначала изучите соответствующий маршрут в server/index.mjs. Генерация не должна запускаться скрытно от пользователя: привязывайте действие к явной кнопке/команде.

## 5. Хранилище и изоляция кампаний

```javascript
const saved = await sas.storage.read(); // {revision, value}
await sas.storage.write({...saved.value, enabled: true}, saved.revision);
await sas.storage.update(value => {
  value.rooms ||= {};
  value.rooms[roomId] = {notes: 'Только эта кампания'};
});
```

Хранилище отделено от state, памяти, канона и чужих расширений. Лимит — 100 КБ JSON на расширение. write требует текущую revision; конфликт возвращает HTTP 409. Frontend update делает до трёх попыток, поэтому callback должен быть чистой функцией, без запросов и побочных эффектов. Backend предоставляет storage.read/write с тем же контрактом.

Для данных истории используйте chat.id, для комнаты — room.id, для фанфика — project.id/episode.id. Не выбирайте «последнюю» историю и не переносите общую переменную memory между режимами. После удаления плагина хранилище сохраняется, чтобы переустановка не уничтожала заметки. Никакая запись storage сама по себе не становится лорбуком или памятью LLM.

## 6. Backend API и собственные функции НРИ

Добавьте "backend": "server.mjs" в manifest. Backend запускается на компьютере/сервере владельца, один раз на включённый экземпляр SAS, а не в браузере каждого клиента. Он может использовать встроенные модули Node.js и собственные файлы пакета. Для сторонних npm-зависимостей поставляйте собранный модуль: зависимости установленного приложения не считаются API расширения.

```javascript
export async function activate(sas) {
  sas.route('get', '/status', async (req, res) => {
    res.json({extension: sas.id, value: await sas.storage.read()});
  });
  sas.route('post', '/custom-check', async (req, res) => {
    sas.tasks.assertIdle();
    // Здесь валидируйте участников, очередь, параметры и собственную формулу.
    res.json({ok:true});
  });
}
```

Frontend вызывает request('/extensions/my-extension/actions/status'). Методы route: get, post, put, patch, delete. URL начинается с /. Ошибки handler преобразуются в JSON-ошибку SAS. После выключения маршруты недоступны. Backend getState() возвращает снимок; saveState(next) использует серверное сохранение и запрещён во время генерации. Для игровых действий предпочтительны штатные /multiplayer/game и движок, а не прямая запись HP: штатные действия сохраняют очередь и журнал. Специализированную механику собственной НРИ можно реализовать своим маршрутом с явной проверкой игрового состояния и журналированием.

Файлы backend не выдаются через frontend file endpoint. Это не место для секретов: никогда не кладите ключи в frontend или распространяемый ZIP. Учётные данные LLM не входят в getState().

## 7. Дополнение контекста LLM

```javascript
// manifest: "modes": ["dnd", "custom"]
export function activate(sas) {
  sas.onPrompt(({mode, chatId}) => {
    return 'Сохраняй стиль хроники. Результаты движка не пересчитывай.';
  }, {modes:['dnd', 'custom']});
}
```

Это backend hook, он возвращает строку или Promise строки. Модули не могут подписаться на режим, не объявленный в manifest.modes. Режимы: roleplay (одиночный RP), multiplayer-roleplay, dnd, custom, fanfic. По умолчанию modes пуст, поэтому плагин ничего не добавляет в контекст. Hook получает mode и chatId/content для RP/комнат, либо projectId/episodeId/request для фанфика. Для room-контекста chatId имеет вид room-<room.id>.

Один блок ограничен 4000 символами, сумма — 12000. Они учитываются при сборке и проверке размера контекста; слишком большие инструкции не должны обходить окно модели. Плагиновые инструкции не записываются в хронику, память или канон автоматически. Ошибка hook выводится в карточке расширения; это не повод подмешивать данные другого режима. Сигнал context.signal (первый аргумент hook) предназначен для отмены своих асинхронных запросов; не делайте тяжёлую синхронную работу в процессе SAS. Ожидание backend import/activate ограничено 5 секундами, prompt hook — 4 секундами. Таймаут не может остановить блокирующий JavaScript: тяжёлые операции выносите в Worker/дочерний процесс и завершайте его в cleanup.

## 8. Упаковка, обновление и отладка

```text
my-extension/
  manifest.json
  index.js
  style.css
  server.mjs
```

Из корня исходников: node scripts/package-extension.mjs /путь/my-extension /путь/my-extension.zip. Упаковщик проверяет тот же формат, что сервер. Допустимы JS/MJS, CSS, JSON, TXT, MD, HTML, SVG, PNG, JPG, WebP. До 120 файлов, до 4 МБ на файл и до 10 МБ всего. Не допускаются абсолютные пути, .., скрытые каталоги, symlinks и архивы с внешней корневой папкой. manifest.json зарезервирован для метаданных, package.json создаётся SAS для ES-модулей.

Установка пакета с тем же id выключает старую версию; новую нужно включить заново. id хранилища остаётся прежним. Все ресурсы новой версии получают отдельные URL, чтобы браузер не смешал JS разных обновлений. Ошибки активации показываются в списке расширений. Проверьте выключение: страницы/кнопки/CSS/подписки исчезают, таймеры и собственные соединения закрываются вашей cleanup-функцией.

## 9. Безопасный запуск и FAQ

Поле manifest.permissions объявляет реальный уровень доверия: frontend требует `studio:full-access` (страница, данные и API SAS), backend — `node:full-access` (все права процесса, включая файлы, сеть и запуск программ). Если есть оба модуля, нужны оба значения. Неизвестные права и пропуск требуемого права отклоняются. Для старых пакетов без поля права выводятся из наличия модулей и показываются до включения. Это декларация полного доступа, а не ограниченная песочница.

При включении интерфейс показывает права и SHA-256 всего пакета. Подтверждение привязано к ревизии и хешу; устаревшее подтверждение отклоняется с HTTP 409. Обновление требует нового согласия. При старте и перед выдачей ресурсов проверяются файлы пакета; изменённый пакет не активируется. Расширения из старых версий без контрольной суммы остаются на диске, но требуют переустановки и повторного согласия; их отдельное хранилище сохраняется.

SHA-256 не является цифровой подписью и не удостоверяет автора. Сверяйте его с доверенным источником; не запускайте непроверенные расширения. Полностью доверенный плагин уже имеет права изменять файлы своего процесса, поэтому проверка хеша не защищает от кода, которому ранее разрешён полный доступ.

При прямом обращении к API включение требует `{enabled:true,trusted:true,revision,digest}`; `revision` и `digest` берутся из только что просмотренного списка `/api/extensions`. Поля нельзя переносить с предыдущей версии пакета.

Если SAS перестал запускаться после установки кода, задайте SAS_DISABLE_EXTENSIONS=1 перед запуском. Исходники Windows включают Start-SAS-Safe.cmd, веб-архив — Start-SAS-Web-Safe.cmd. В этом режиме backend-модули и frontend-модули не запускаются, истории и настройки сохраняются; можно удалить неисправный плагин. После удаления перезапустите обычным способом.

Можно полностью переделать интерфейс? Да: страницы, панели, CSS, DOM, команды и доверенный backend. Такой код может сломать оболочку; стабильными считаются описанные SDK-методы и слоты, а не внутренности React.

Работает офлайн? Да, если пакет содержит все свои ресурсы и сам не делает внешних запросов.

Можно поставить JS от SillyTavern? Его API и DOM отличаются. Переносите расширение на SAS SDK; прямой совместимости нет. Карточки, лорбуки, пресеты и Regex ST импортируются отдельно.

Работает в веб-версии? Да, в полном интерфейсе SAS и графической оболочке общего backend. На отдельной странице гостя комнаты произвольный код хоста не запускается автоматически. Backend дополнение выполняется у хоста; игровое состояние, изменённое корректным серверным действием, синхронизируется обычным механизмом комнаты.

Нужна ли пересборка Electron для установки? Нет. После установки и включения модули подгружаются из каталога данных. Перезапуск нужен только для восстановления безопасным режимом или если этого требует само расширение.

## 10. Лицензия и публикация расширений

Для самостоятельного расширения укажите автора, версию, лицензию и зависимости. Его автор выбирает условия распространения; при копировании кода SAS сохраняются Apache-2.0 и применимые уведомления. Добавьте исходники пакета или ссылку на репозиторий, описание доступа к сети и файлам и перечень поддерживаемых режимов. Не выдавайте стороннее расширение за официальное дополнение проекта. Пример в `examples/sas-extensions/campaign-notes` можно использовать по лицензии SAS с сохранением уведомлений.
