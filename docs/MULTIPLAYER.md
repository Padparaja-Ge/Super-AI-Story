# Мультиплеер и лорбуки

## Сохранённые истории

Перед открытием комнаты выберите новую или сохранённую историю. Закрытие комнаты сохраняет текущую историю. Для удаления закройте комнату, выберите сохранение и нажмите «Удалить историю». Старые сообщения, сцена и лор не переходят в новую историю.

## Создание комнаты

В «Мультиплеер → Создать комнату» выберите историю с нужным персонажем ведущего, название, порт и свою персону. Подключение к LLM и пресет берутся из выбранной истории. Личная память, сводка и сообщения одиночной истории в комнату не добавляются.

После открытия комнаты хост выбирает лорбуки в блоке «Ведущий и лор». Их названия видят все участники. Пустой список означает игру без лора; выбор комнаты независим от одиночных историй. Кнопка «Пригласить» копирует ссылку с кодом доступа. Гостю нужен сетевой адрес компьютера хоста; адрес `127.0.0.1` подходит только для подключения с того же компьютера.

## Подключение гостя

В настольном SAS и полной веб-версии откройте «Мультиплеер → Подключиться к комнате», вставьте приглашение и выберите свою персону. Либо откройте приглашение непосредственно в браузере: страница позволяет создать или импортировать персону перед входом. Описание выбранной персоны передаётся хосту для контекста общей игры.

Гостю доступны сообщение, бросок d4/d6/d8/d10/d12/d20/d100, улучшение черновика, выход и экспорт доступной истории в JSON. Экспорт включает исправленные сообщения и сведения о прикреплённых изображениях; сами файлы изображений в JSON не встраиваются. Комната хранит последние 300 сообщений.

## Очередность

Хост задаёт целое значение от 0 до 999 каждому игроку и ведущему. Меньшее значение ходит раньше; при одинаковых значениях участники выбирают порядок внутри своей группы. Применение настроек начинает новый раунд. Если все значения равны нулю, действует свободный режим.

Например, хост — 1, гость — 2, ведущий — 3: сначала пишет хост, затем гость, затем хост нажимает «Ход ведущего». Только после ответа ведущего начинается следующий раунд. В свободном режиме хост вызывает ведущего в любой момент, когда нет активной генерации.

Сообщение завершает ход игрока. Бросок кубика его не завершает, поэтому результат можно использовать при написании поста. Отключённые игроки и игроки с запретом писать пропускаются. Текущий участник и очередь видны всем. При ошибке отправки черновик сохраняется.

## Права хоста

Хост редактирует любое сообщение; исправление сразу появляется у гостей и используется в следующих запросах к модели. Он может запретить и разрешить игроку писать или отключить его кнопкой «Выгнать». Это отключение текущего участника, а не постоянная блокировка человека по аккаунту.

Изображения создаёт только хост через «Изображение сцены». Его текстовая модель составляет промпт из персонажа, внешности, сцены и сообщений комнаты. После проверки промпта используется настроенный у хоста API-workflow ComfyUI, включая выбранную модель, LoRA и остальные ноды. Готовое изображение появляется в общей истории. Гостям доступны только опубликованные изображения комнаты.

## Улучшение текста на стороне гостя

При подключении через свой SAS выберите собственную модель или API в поле «Ваше подключение для улучшения текста». «Улучшить моей моделью» создаёт вариант черновика через ваше ядро SAS. Результат вставляется по отдельной кнопке и не отправляется в комнату автоматически.

На странице приглашения в обычном браузере укажите адрес **своего** запущенного SAS в разделе локального улучшения. Кнопка открывает редактор на вашем SAS, где вы выбираете подключение, запускаете улучшение и возвращаете результат в черновик. Без своего SAS эта функция недоступна; остальные функции гостя работают. Ключи модели остаются в вашем ядре и не передаются серверу комнаты.

## Лор в одиночной игре

В «Персонажи» откройте карточку и отметьте нужные лорбуки. Неотмеченные книги к этому персонажу не применяются. Раздел «Лорбуки» хранит библиотеку и редактирует записи; глобального выключателя книги, который переопределял выбор карточки, больше нет. Отдельные записи по-прежнему можно выключать.

Существующие явные привязки карточек сохраняются. Если у старой карточки книги не были выбраны, после обновления она использует пустой список: нужные книги следует отметить в карточке. В новых историях заголовок — имя персонажа; уже сохранённые названия не переименовываются.
